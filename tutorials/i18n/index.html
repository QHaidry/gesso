    Translate an application¶

    You will end up with two catalogs, correct plural forms, a language that follows the system when it should, and a user override that wins.

    No Qt. About fifteen minutes.

    1. Write a catalog¶

    A catalog is JSON, looked up by dotted key. examples/tutorials/locales/en.json:

    {
  "greeting": {
    "title": "Pomodoro",
    "hello": "Hello, {name}!",
    "labelled": "Press {key} to continue.",
    "items": {
      "one": "{count} item",
      "other": "{count} items"
    }
  }
}

    There is nothing to compile and no .po/.mo step: the catalogs ship as-is and are read at runtime.

    2. Point a translator at them¶

    from gesso.i18n import DEFAULT_LANGUAGE, DirectorySource, Translator, detect_language

translator = Translator(
    [DirectorySource(LOCALES, name="application")],
    language=detect_language() or DEFAULT_LANGUAGE,
    fallback=DEFAULT_LANGUAGE,
    include_framework=False,
)

    detect_language() reads LANGUAGE, LC_ALL, LC_MESSAGES and LANG, in that order, and returns "" for the values that mean "unset" — C, POSIX, and an unset variable. That is why it is or DEFAULT_LANGUAGE and not a default argument: an empty detection is a real answer, not a missing one.

    $ python examples/tutorials/greeting.py
detected from the environment: en
active language:  en

    $ LANGUAGE=fr_FR.UTF-8 python examples/tutorials/greeting.py
detected from the environment: fr
active language:  fr

    3. Look things up¶

    translator.t("greeting.hello", name="Ada")     # 'Hello, Ada!'

    {name} is filled from the keyword arguments. A missing key comes back as itself:

    translator.t("greeting.untitled")              # 'greeting.untitled'

    Not an empty string — an empty string looks like a layout bug, while a raw key is visible on screen and greppable in your source.

    The key argument is positional-only

    def t(key_name: str, /, *, default=None, **kwargs) -> str

    That / is load-bearing. A translation is allowed to contain a placeholder called key:

    "labelled": "Press {key} to continue."

    translator.t("greeting.labelled", key="Ctrl+K")   # 'Press Ctrl+K to continue.'

    Without the positional-only marker, key="Ctrl+K" would collide with the parameter of the same name and raise got multiple values for argument 'key'. Gesso found this because a real application wanted to say "press {key}".

    4. Get plurals right, by hand¶

    Gesso does not guess plural rules. The tutorial makes the consequence explicit:

    def count_of(translator, key, count):
    form = "one" if count == 1 else "other"
    return translator.t(f"{key}.{form}", count=count)

      0 -> 0 items
  1 -> 1 item
  2 -> 2 items

    This is not laziness, and it is worth understanding before you reach for one/other in a language you do not speak:

    Language Plural forms
    English, French 2
    Russian, Polish 3
    Arabic 6

    Getting those right needs real CLDR data, which Gesso's roadmap lists as a planned optional backend rather than something the core pretends to have. Until then the catalogs carry the forms and your application chooses — which has the side benefit that the rule is visible in your code instead of hidden in a library's tables.

    If you only ship English, this is the whole rule and you are done.

    5. Let the user override you¶

    Add their directory as a later source:

    sources = [DirectorySource(LOCALES, name="application")]
sources.append(DirectorySource(USER_LOCALES, name="user"))

    Sources are consulted in ascending priority — later wins:

    $ python examples/tutorials/greeting.py --language fr
application only: Pomodoro
with the user's:  Pomodoro (personnalisé)

    The fr.json that produced that second line is four lines:

    { "greeting": { "title": "Pomodoro (personnalisé)" } }

    In a real application that directory lives beside the user's settings (~/.config/<app>/i18n/), not beside your code. It is next to the tutorial only so the example stands alone. Translator.for_app(context, ...) wires that up for you:

    translator = Translator.for_app(context, language=..., locale_dir=LOCALES)

    6. And know which way is right-to-left¶

    is_rtl(translator.language)     # False for 'fr', True for 'ar' or 'he'

    Gesso ships the language list and the question; it does not flip your window for you. run_app applies the direction to the whole application, because Qt mirrors every widget without any of them knowing — which is the only way it is ever going to be done correctly. See the shell tutorial.

    The whole tutorial¶

    """Tutorial: translate an application, and get plurals right.

Run it::

    PYTHONPATH=src python examples/tutorials/greeting.py
    PYTHONPATH=src python examples/tutorials/greeting.py --language fr
    LANGUAGE=fr_FR.UTF-8 PYTHONPATH=src python examples/tutorials/greeting.py
"""

from __future__ import annotations

import sys
from pathlib import Path

from gesso.i18n import (
    DEFAULT_LANGUAGE,
    DirectorySource,
    MappingSource,
    Translator,
    detect_language,
    is_rtl,
    normalize_lang,
)

HERE = Path(__file__).parent
#: The application's catalogs, shipped with the code.
LOCALES = HERE / "locales"
#: A *user's* overrides. Real applications put this beside the user's settings
#: (`~/.config/<app>/i18n/`), not beside their own; it is next to the code here
#: only so the tutorial is self-contained.
USER_LOCALES = HERE / "user-locales"


def build_translator(language: str | None = None, *, user: bool = True) -> Translator:
    """A translator for this tutorial's catalogs.

    Source order is the whole lesson. Sources are consulted in **ascending
    priority**:

    1. Gesso's own `gesso.*` catalogs (skipped here — this app uses none);
    2. the application's, shipped with the code;
    3. the user's, read from beside their settings.

    So a user can override any string without touching the application — the
    same way a user theme overrides a built-in palette.
    """
    sources = [DirectorySource(LOCALES, name="application")]
    if user:
        sources.append(DirectorySource(USER_LOCALES, name="user"))

    return Translator(
        sources,
        language=language or detect_language() or DEFAULT_LANGUAGE,
        fallback=DEFAULT_LANGUAGE,
        include_framework=False,
    )


def count_of(translator: Translator, key: str, count: int) -> str:
    """Choose the ``.one`` or ``.other`` form of *key* for *count*.

    Gesso does not guess plural rules, and this function is the honest
    consequence. English and French really do have two forms; Russian has
    three and Arabic six, and getting those right needs real CLDR data. So the
    catalogs carry the forms and the application picks — which also means the
    rule stays visible in your code instead of hiding in a library's tables.
    """
    form = "one" if count == 1 else "other"
    return translator.t(f"{key}.{form}", count=count)


def main(argv: list) -> int:
    requested = None
    if "--language" in argv:
        requested = argv[argv.index("--language") + 1]

    print(f"detected from the environment: {detect_language() or '(nothing)'}")
    print(f"normalised:                    {normalize_lang('fr_FR.UTF-8')!r}")
    print()

    translator = build_translator(requested)
    print(f"active language:  {translator.language}")
    print(f"right to left?    {is_rtl(translator.language)}")
    print(f"catalogs provide: {translator.languages()}")
    print()

    print(f"  title    {translator.t('greeting.title')}")
    print(f"  hello    {translator.t('greeting.hello', name='Ada')}")
    print(f"  goodbye  {translator.t('greeting.goodbye', name='Ada')}")

    # A placeholder called `key` is safe, because the translation key is
    # positional-only. That is what `t(key_name, /, **kwargs)` is for.
    print(f"  labelled {translator.t('greeting.labelled', key='Ctrl+K')}")

    print("  counts:")
    for count in (0, 1, 2):
        print(f"    {count} -> {count_of(translator, 'greeting.items', count)}")

    # A key nobody defined comes back as *itself*: visible on screen, greppable
    # in the source, and never an empty string that looks like a layout bug.
    print(f"  missing  {translator.t('greeting.untitled')!r}")

    # ------------------------------------------------------------------
    # The user's overrides, which win because they were consulted last
    # ------------------------------------------------------------------
    application_only = build_translator(requested, user=False)
    print(f"\napplication only: {application_only.t('greeting.title')}")
    print(f"with the user's:  {translator.t('greeting.title')}")

    # A catalog can also live in memory: handy for tests, and for strings that
    # are generated rather than written.
    in_memory = Translator(
        [MappingSource({"en": {"greeting": {"hello": "Hi {name}!"}}})],
        language="en",
        include_framework=False,
    )
    print(f"in memory:        {in_memory.t('greeting.hello', name='Ada')}")
    return 0


if __name__ == "__main__":
    raise SystemExit(main(sys.argv[1:]))

    Check it works¶

    $ PYTHONPATH=src python examples/tutorials/greeting.py
$ PYTHONPATH=src python examples/tutorials/greeting.py --language fr
$ LANGUAGE=fr_FR.UTF-8 PYTHONPATH=src python examples/tutorials/greeting.py

    The test that actually saves you¶

    A missing translation does not fail. It prints English. Nothing raises, your tests stay green, and the bug ships.

    The only cheap defence is comparing the catalogs key-for-key:

    def keys_of(catalog, prefix=""):
    found = set()
    for key, value in catalog.items():
        path = f"{prefix}.{key}" if prefix else key
        found |= keys_of(value, path) if isinstance(value, dict) else {path}
    return found


def test_the_catalogs_cover_the_same_keys():
    assert keys_of(load_catalog("en")) == keys_of(load_catalog("fr"))

    Two more from the examples are worth stealing:

    # Every key resolves, rather than coming back as itself.
unresolved = [k for k in sorted(keys_of(catalog)) if translator.t(k) == k]
assert unresolved == []

    That one catches a dotted key name written inside JSON. "theme.help": "…" is a literal key, not a nested one, so the lookup walks into the string "Palette" and gives up — silently. Tracker shipped five of those until a test like this found them.
