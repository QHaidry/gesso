    Store a setting¶

    You will end up with a settings file that types itself, refuses values it should not hold, and can be rewritten in another format.

    No Qt. About ten minutes.

    1. Say who the application is¶

    from gesso.core import AppContext, AppSpec, AppPaths

APP = AppSpec(
    name="Pomodoro",
    app_id="pomodoro",
    version="0.1.0",
    default_config_format="json",
)

    app_id is the directory name, so you never type a path. AppSpec is covered in Application identity.

    2. Say what it remembers¶

    SCHEMA = Schema(
    [
        Section(
            "timer",
            title="Timer",
            options=(
                Option("minutes", int, 25, "Length of a session.", minimum=1, maximum=180),
                Option("label", str, "Focus", "What the session is called."),
                Option("chime", bool, True, "Play a sound at the end."),
                Option("mode", str, "work", "Which mode to start in.",
                       choices=("work", "break")),
            ),
        )
    ]
)

    That is the entire specification of what persists: two strings, an integer and a boolean. Each has a default, and three of the four carry a constraint.

    3. Open the store¶

    paths = AppPaths.resolve(APP.app_id, config_home=Path("pomodoro-home"))
store = ConfigStore.for_app(SCHEMA, AppContext(APP, paths)).load()

print(store.path)        # pomodoro-home/pomodoro/config.json
print(store.exists())    # False — nothing is written until there is something to write

    Two things to notice already:

    • --config-home in the tutorial stands in for $XDG_CONFIG_HOME. Nothing writes to your real ~/.config, which is also what lets the test suite run without side effects.
    • Reading does not create a file. Starting an application should not litter.

    4. Read a value: it is already the right type¶

    minutes = store.get("timer.minutes")
print(repr(minutes))     # 25
print(type(minutes).__name__)   # int

    There is no getint. There is no int(store.get(...)), no getboolean, and no "true" anywhere in your code. The schema is the only place the type is written down, and the store is where it is applied.

    5. Write a value: coercion is the schema's job¶

    store.set("timer.minutes", "50")     # a string, on purpose
store.set("timer.chime", "no")       # also not a boolean
store.save()

    Both of those are accepted. Coercion turns "50" into an integer and "no" into False, so a command-line tool, a web form and a config file all work without the caller helping.

    $ python examples/tutorials/settings.py
settings live in pomodoro-home/pomodoro/config.json
file exists yet? False
minutes: 25 (int)
after saving: 50, False
problems: none

    6. Watch a bad value get refused¶

    Constraints are enforced in two places, and it matters which is which:

    When What it does
    Schema.validate() when you ask reports everything wrong with the data on disk
    ConfigStore.set() at the call site rejects, and does not store 
    $ python examples/tutorials/settings.py --break
refused: timer.minutes: 999 exceeds the maximum of 180
refused: timer.mode: 'siesta' is not one of: work, break
after saving: 50, False

    999 is a perfectly good integer. The schema is what refuses it, and the message names the bound rather than saying "invalid". The refused values never reached the file — the saved minutes is still 50.

    Why both?

    A value can be unacceptable for two different reasons. 999 cannot be coerced — it is a valid integer, just out of range. "lots" cannot be read as an integer at all. Gesso reports them the same way because from the outside they are the same problem: this setting is not usable, and you would rather know now than at three in the morning.

    The split matters because validate() has to cope with a file a human edited, while set() is the last moment you have the caller's attention.

    7. Change the format without changing the code¶

    reloaded.convert_to("toml")

    $ python examples/tutorials/settings.py --toml
rewritten as toml: pomodoro-home/pomodoro/config.toml

    The old file is kept as a .bak. And if the format you asked for has no writer installed:

    $ python examples/tutorials/settings.py --toml
cannot convert: writing TOML requires the 'tomli-w' package (pip install 'gesso-sdk[toml]')

    That is the design, not a shortcoming: a codec that cannot write says so rather than quietly writing a second config file in a format it can manage. Two config files is a bug you find months later.

    The whole tutorial¶

    """Tutorial: store a setting, and refuse a bad one.

Run it::

    PYTHONPATH=src python examples/tutorials/settings.py
    PYTHONPATH=src python examples/tutorials/settings.py --break
    PYTHONPATH=src python examples/tutorials/settings.py --toml
"""

from __future__ import annotations

import sys
from pathlib import Path

from gesso.config import ConfigError, ConfigStore, Option, Schema, Section
from gesso.core import AppContext, AppSpec, AppPaths

# ----------------------------------------------------------------------
# 1. What is this, and what does it remember?
# ----------------------------------------------------------------------
APP = AppSpec(
    name="Pomodoro",
    app_id="pomodoro",
    version="0.1.0",
    default_config_format="json",
)

SCHEMA = Schema(
    [
        Section(
            "timer",
            title="Timer",
            options=(
                Option("minutes", int, 25, "Length of a session.", minimum=1, maximum=180),
                Option("label", str, "Focus", "What the session is called."),
                Option("chime", bool, True, "Play a sound at the end."),
                Option(
                    "mode",
                    str,
                    "work",
                    "Which mode to start in.",
                    choices=("work", "break"),
                ),
            ),
        )
    ]
)


def open_store(name: str, config_home: Path) -> ConfigStore:
    """Find (or plan) the settings file for an application called *name*."""
    spec = APP if name == APP.app_id else AppSpec(name=name, app_id=name, version="0.1.0")
    paths = AppPaths.resolve(spec.app_id, config_home=config_home)
    return ConfigStore.for_app(SCHEMA, AppContext(spec, paths)).load()


def main(argv: list) -> int:
    config_home = Path("pomodoro-home")
    store = open_store("pomodoro", config_home)
    print(f"settings live in {store.path}")
    print(f"file exists yet? {store.exists()}")

    # Settings come out of the store already typed. There is no getboolean.
    minutes = store.get("timer.minutes")
    print(f"minutes: {minutes!r} ({type(minutes).__name__})")

    if "--break" in argv:
        # A value the schema refuses never reaches the file.
        try:
            store.set("timer.minutes", 999)
        except ConfigError as exc:
            print(f"refused: {exc}")
        try:
            store.set("timer.mode", "siesta")
        except ConfigError as exc:
            print(f"refused: {exc}")

    # A *string* is fine: coercion is the schema's job, not the caller's.
    store.set("timer.minutes", "50")
    store.set("timer.chime", "no")
    store.save()

    reloaded = open_store("pomodoro", config_home)
    print(f"after saving: {reloaded.get('timer.minutes')!r}, {reloaded.get('timer.chime')!r}")

    if "--toml" in argv:
        try:
            reloaded.convert_to("toml")
            print(f"rewritten as {reloaded.format}: {reloaded.path}")
        except ConfigError as exc:
            # A codec that cannot write says which package to install, rather
            # than writing a second config file in a format it can manage.
            print(f"cannot convert: {exc}")

    problems = reloaded.validate()
    print(f"problems: {problems or 'none'}")
    return 0


if __name__ == "__main__":
    raise SystemExit(main(sys.argv[1:]))

    Check it works¶

    $ PYTHONPATH=src python examples/tutorials/settings.py
$ PYTHONPATH=src python examples/tutorials/settings.py --break
$ PYTHONPATH=src python examples/tutorials/settings.py --toml
$ cat pomodoro-home/pomodoro/config.json
