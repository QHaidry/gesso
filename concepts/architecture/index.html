    Architecture¶

    Gesso is organised in tiers, layered by dependency weight. The goal is simple: a command-line tool should pay nothing for a graphical toolkit it will never open.

    The dependency rule¶

    An application depends on Gesso. Gesso never depends on the application.

    Everything Gesso needs to know about your application arrives as an :class:~gesso.core.AppSpec. Gesso never imports your code, never reads a hard-coded path for you, and never assumes there is only one application in the world. Break this rule and the SDK stops being reusable; it becomes a framework you are trapped inside.

    Tier 3 is imported lazily. Importing gesso on a machine with no Qt installed must never fail.

    What Gesso deliberately does not do¶

    An SDK earns its keep by what it refuses to include. Gesso has no opinion about:

    • Your domain. No wallpapers, no documents, no editor buffers. Those belong to the application.
    • Your dependency injection. Gesso takes plain constructor arguments; it does not require a container or a plugin registry.
    • Your framework. AppContext is an ordinary object you can construct in a test, not a global you have to mock.

    How an application plugs in¶

    Every tier takes the same small handle — an AppContext — so wiring an application is a two-step affair:

    from gesso.core import AppContext, AppSpec

spec = AppSpec("My App", app_id="myapp", version="1.0.0")  # who
context = AppContext(spec)                                 # who + where

    Pass context to whatever you need, and construct it with an injected AppPaths when you want an isolated profile (tests, portable installs):

    from gesso.core.paths import AppPaths

sandboxed = AppContext(spec, AppPaths.resolve(spec.app_id, config_home=tmp_path))

    That is the whole extension mechanism. There is no plugin API to learn because there is no framework to fight.
